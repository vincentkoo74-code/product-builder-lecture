# iOS UI Changes For Android Sync

작성일: 2026-06-04

이 문서는 iOS 앱 테스트 중 반영한 UI/UX 수정 사항을 Android 앱에도 동일하게 적용하기 위한 기준 문서입니다.

## 버튼 그룹 규칙

- 액션 버튼 그룹은 기본적으로 한 줄에 2개씩 배치한다.
- 마지막 줄에 버튼이 1개만 남으면, 버튼 크기는 2열 버튼 1개와 같은 폭으로 유지하고 화면 가운데 정렬한다.
- 버튼과 버튼 사이 간격은 동일하게 유지한다.
- 참가자 목록, 벌칙/게임 정보, 버튼 그룹처럼 기능이 다른 그룹 사이 간격은 버튼 사이 간격보다 넓게 둔다.
- 적용 대상 예:
  - 준비 완료 / 나가기
  - 게임 시작 / 벌칙 수정 / 처음으로
  - 벌칙 저장 / 돌아가기
  - 다음 라운드 / 게임 종료
  - 최종 결과 화면 버튼들

## 참가자 목록 규칙

- iPhone Pro와 iPhone Air 모두 참가자 명단은 한 줄에 2명씩 표시한다.
- 좁은 화면에서도 1열로 떨어지지 않도록 2열 그리드를 강제한다.
- 참가자 이름과 상태 배지는 긴 텍스트일 경우 말줄임 처리한다.

## QR 화면 변경

- QR 스캔 화면의 `방코드 직접 입력` 이동 버튼을 제거했다.
- 같은 위치에 `방 코드 입력칸 | 입장 버튼`을 한 줄 2칸으로 배치했다.
- 방 코드 입력값은 영문/숫자만 허용하고 자동 대문자 변환한다.
- QR 스캔 성공 시 별도 직접 입력 화면으로 이동하지 않고 즉시 입장 흐름으로 연결한다.
- 호스트 방 화면의 로컬 테스트용 `스마트폰 QR 접속 주소` 입력 박스는 상용 iOS 화면에서 제거한다.

## 로그인/게스트 기록 분리

- 게스트 상태에서 만든 최근 방 기록과 게임 결과는 SNS 로그인 후 화면에 노출하지 않는다.
- `rpsRecentRoomCodes`, `rpsPartyState`, 라운드 아카이브는 인증 상태별 저장소로 분리한다.
- 기존 무스코프 로컬 기록은 게스트 기록으로만 취급하고, SNS 로그인 상태에서는 읽지 않는다.
- 게스트에서 SNS 로그인으로 전환되는 순간 현재 메모리에 남아 있던 방 코드, 참가자, 결과, 대기실 상태를 초기화한다.
- 로그인 계정의 누적 기록은 Supabase 계정 기록 또는 로그인 스코프 저장소만 사용한다.

## 앱 아이콘

- iOS 기본 앱 아이콘은 한글 버전 `AppIcon`을 사용한다.
- 영문 버전은 `AppIconEnglish`, 일본어 버전은 `AppIconJapanese` 대체 아이콘 세트로 둔다.
- 세 아이콘 모두 1024×1024 PNG, alpha 없음 형식으로 생성한다.
- 웹/Android 동기화를 위해 원본 아이콘은 `ASSETS/rps/app-icon-ko.png`, `ASSETS/rps/app-icon-en.png`, `ASSETS/rps/app-icon-ja.png`에도 보관한다.
- 언어별 아이콘 매핑은 `APP_ICON_VARIANTS` 기준을 따른다.
- iOS에서는 `MainViewController`가 `AppIconPlugin` 네이티브 브릿지를 등록하고, 언어 변경 시 `ko`는 기본 아이콘, `en`은 `AppIconEnglish`, `ja`는 `AppIconJapanese`로 전환한다.
- 홈 화면에서 검정 테두리처럼 보이던 바깥 배경은 제거하고 금색 배경으로 채웠다. 한/영/일 아이콘 모두 같은 크롭/채움 규칙을 적용해 아이콘이 홈 화면 칸을 더 꽉 채우도록 한다.

## 닫기 버튼 정렬

- 팝업과 화면 닫기 버튼은 원형 버튼 중앙에 X가 정확히 정렬되도록 통일했다.
- 문자 X 대신 두 개의 중앙 정렬 선으로 X를 그린다.

## 게임 진행 흐름

- 게임 종료 후 자동으로 다음 게임/로비로 넘어가지 않는다.
- 무승부, 술래 수 초과, 술래 수 부족 상황도 호스트가 버튼을 눌러야 다음 라운드로 진행된다.
- 무승부 또는 술래 미확정으로 재대결이 필요한 경우 호스트 버튼 문구는 `다시해!`로 표시한다.
- 재대결 버튼 안의 별도 `NEXT` 보조 라벨은 삭제해 텍스트 겹침과 버튼 과밀을 방지한다.
- 큰 라운드(`gameRound`)와 재대결(`round`)을 분리한다. `gameRound`는 새 게임판, `round`는 같은 게임판 안의 재대결 번호다.
- 같은 `gameRound` 안에서 무승부/술래 미확정으로 이어지는 재대결은 승/무/패 누적을 유지한다.
- 새 `gameRound`가 시작되면 선택값, 준비 상태, 승/무/패, 벌칙 카운트, 확정 술래/안전자 목록을 모두 초기화한다.
- 새 `gameRound` 시작은 공통 함수 한 곳에서 처리해 모든 경로의 초기화 규칙을 동일하게 유지한다.
- 라운드 결과 카드의 라운드 번호는 오래된 `penalty.gameRound`만 믿지 않고, `penalty.gameRound`와 로컬 `state.gameRound` 중 최신 유효값을 기준으로 표시한다.
- `penalty.gameRound`가 없거나 오래된 값이면 `state.gameRound`로 보정하고, 새 방에 입장할 때는 방의 `penalty.gameRound`로 로컬 값을 초기화한다.
- 로비에서 게임을 시작할 때 현재 `gameRound`가 이미 시작했던 번호와 같으면 새 게임판 시작 직전에 자동으로 다음 번호로 올려 같은 라운드 번호가 재사용되지 않게 한다.
- 게임 화면에 실제 진입한 순간의 `gameRound`를 `lastStartedGameRound`로 저장해 다음 새 게임 시작 시 번호 중복 여부를 판단한다.
- 각 `gameRound`의 첫 대결이 시작되거나 완료된 뒤 참가자 ID 또는 호스트가 바뀌면 기존 라운드는 종료된 것으로 보고, 기존 통계를 기록한 뒤 새 `gameRound`로 리셋한다.
- 호스트 이탈, 호스트 양도, 술래의 다음 호스트 승격, 참가자 입장/퇴장/자동 퇴출은 첫 대결 이후라면 모두 새 `gameRound` 리셋 조건이다.
- 새 게임 시작은 호스트 기기만 먼저 출발하지 않도록 방 상태 변경 기준으로 동기화한다.
- 목표 술래 수가 채워진 최종 종료는 `game_over` 상태로 분리한다.
- `game_over` 상태에서는 자동으로 다음 라운드 준비 화면으로 넘어가면 안 된다.
- 최종 종료 후 다음 게임은 호스트가 `한번더` 버튼을 눌렀을 때만 새 로비/벌칙/준비 흐름으로 시작한다.
- 호스트가 최종 종료 후 `한번더`를 누르면 결과 화면의 임시 버튼, 카운트다운, 라운드 타이머를 먼저 정리하고 즉시 로비 화면으로 이동한다.
- 새 게임 초기화 함수가 로컬 상태를 먼저 바꿔도 DB 이벤트에서 “상태 변경 없음”으로 오판해 결과 화면이 남지 않도록, `한번더` 처리 경로에서 화면 전환을 직접 수행한다.
- `playing` 신호 수신 후 화면 진입은 호스트와 참가자가 같은 전용 함수로 처리한다.
- `gameStarting`은 버튼 중복 클릭 방지용으로만 사용하고, 호스트의 `playing` 화면 진입을 막는 조건으로 사용하지 않는다.
- 호스트가 `게임 시작`을 눌러 DB 상태를 `playing`으로 바꾼 직후에도 로컬에서 동일한 화면 진입 함수를 호출해 Realtime/폴링 타이밍 차이로 멈추지 않게 한다.
- 같은 `playing` 신호가 Realtime과 폴링으로 중복 도착해도 방 코드, 게임 라운드, 재대결 번호로 만든 진입 키를 사용해 카운트다운이 중복 실행되지 않게 한다.
- 카운트다운은 각 기기가 `playing` 신호를 받은 순간 바로 시작하지 않고, 호스트가 방 상태와 함께 저장한 `countdownStartAt` 공동 시작 시각을 기준으로 시작한다.
- 호스트는 `게임 시작`/`재대결 시작` 시 현재 시각보다 약 2.5초 뒤의 `countdownStartAt`을 저장해 참가자 기기에 Realtime이 도착할 버퍼를 준다.
- 카운트다운 음성은 UI 진행을 `await`로 붙잡지 않는다. 음성 엔진 속도 차이 때문에 기기별 카운트다운 시간이 달라지는 문제를 막기 위해 화면 애니메이션은 고정 시간으로 진행한다.
- 가위/바위/보 선택 버튼은 DB 저장 응답을 기다리지 않고 즉시 로컬 UI에 선택 상태와 선택 이미지를 표시한다. DB 저장 실패 시에는 안내만 표시하고 다음 동기화에서 서버 상태를 따른다.
- 참가자 변경 Realtime 이벤트가 짧은 시간에 여러 번 들어오면 DB 조회와 전체 렌더를 합쳐서 처리한다. 장시간 플레이 중 요청/렌더가 쌓여 버퍼링되는 문제를 줄이기 위한 규칙이다.
- 참가자 목록 동기화 중 네트워크/DB 오류가 나도 동기화 잠금 상태가 반드시 풀리도록 처리한다. 한 번의 실패 때문에 이후 선택/참가자 갱신이 계속 밀리는 현상을 막기 위한 규칙이다.
- 라운드 선택 타이머가 끝날 때는 라운드 타이머만 멈추고, 방 Realtime 백업 폴링은 끄지 않는다.
- 재접속 또는 상태 동기화 후에도 `__loser__` 마커가 있으면 술래 확정 화면을 정확히 보여준다.
- 앱 시작 초기화는 DOM 준비 후 실행하고, 초기화 중 오류가 나도 홈/로그인 화면으로 복구한다. 특정 iPhone WebView에서 저장 상태 복원 중 흰 화면으로 멈추는 문제를 막기 위한 규칙이다.
- 공통 렌더 함수는 선택 화면에 없는 요소를 직접 만지지 않고 존재 여부를 확인한 뒤 갱신한다. 화면별 DOM 차이로 시작 렌더가 중단되지 않아야 한다.

## 가위바위보 선택 버튼

- 게임 화면의 가위/바위/보 선택지는 모든 iPhone 화면에서 한 줄 3칸으로 고정한다.
- iPhone Air처럼 표시 영역이 좁은 기기에서도 세로 3줄로 떨어지지 않아야 한다.
- 선택 카드 안의 마루 손 이미지와 텍스트는 칸 폭에 맞춰 자동 축소한다.

## 호스트/참가자 역할 분리

- 참가자가 방에 들어갈 때 같은 닉네임의 호스트 프로필을 재사용하면 안 된다.
- 수동 방코드/QR 입장 흐름에서는 기존 참가자 프로필만 재사용하고, 호스트 프로필은 절대 참가자에게 할당하지 않는다.
- 중복 참가자 정리 로직은 호스트 행을 삭제하거나 새 참가자를 호스트로 승격하면 안 된다.
- 호스트 기기에는 QR/벌칙수정/게임시작이 포함된 호스트 화면이 보여야 한다.
- 참가자 기기에는 참가자 대기/준비 화면이 보여야 하며, 호스트 전용 QR/벌칙수정 화면이 표시되면 안 된다.

## 로비 정보 표시

- 로비 상단 정보줄은 호스트 화면에서는 `호스트 - 호스트 닉네임`을 표시한다.
- 로비 상단 정보줄은 참가자 화면에서는 `나 - 내 닉네임`을 표시한다.
- 방 코드는 호스트와 참가자 모두 같은 위치에 표시한다.
- 술래 숫자는 호스트와 참가자 모두에게 표시한다.
- 참가자는 술래 숫자를 볼 수만 있고 수정할 수 없다.

## 호스트 단일 판정/결과 동기화

- 온라인 게임 판정은 각 기기에서 개별 계산하지 않고 호스트 기기 한 곳에서만 계산한다.
- 호스트는 참가자의 선택이 모두 수집되면 선택값과 판정값을 함께 저장한다. 예: `scissors|win`, `paper|lose`, `rock|draw`.
- 참가자 기기는 저장된 판정값만 읽어서 결과 화면, 선택 이미지, 승/패/무 배지, 전광판을 렌더링한다.
- 결과 화면 진입 시 저장된 판정값이 있으면 다시 `judgeRound()`를 실행하지 않는다.
- 선택 이미지 파일명은 저장값 전체가 아니라 기본 선택값(`scissors`, `rock`, `paper`)만 사용한다.
- 최종 종료(`game_over`) 시에도 선택 이미지와 판정 표시가 사라지지 않도록 참가자의 `choice`를 즉시 `__safe__`/`__loser__`로 덮어쓰지 않는다.
- 전광판 통계(`wins`, `losses`, `draws`, `penalties`)는 호스트가 판정 저장과 함께 한 번만 업데이트한다.
- 라운드 결과 카드의 승/무/패 숫자는 전체 참가자 수 합산이 아니라 현재 사용자 자신의 `wins/draws/losses` 누적값을 표시한다.
- 예: 2명이 모두 비긴 첫 대결은 전체 무승부 참가자 수 2가 아니라 각 사용자 화면에 `1무`로 표시한다.
- 두 번째 대결에서 호스트가 이기면 호스트 화면은 `1승 1무`, 참가자 화면은 `1무 1패`처럼 각자의 기록으로 누적한다.
- 이 값도 각 기기에서 재판정하지 않고 호스트가 저장한 참가자별 `wins/draws/losses` 값을 읽어 표시한다.
- 최종 종료 화면에서도 방금 끝난 라운드의 승/패가 0으로 남지 않고 누적 기록으로 반영되어야 한다.
- 라운드 결과 카드에는 `승 / 무 / 패 / 목표 술래` 4개 항목을 표시한다.
- `무` 카운트는 호스트가 저장한 `choice|draw` 판정값을 모든 기기에서 동일하게 읽어 계산한다.
- 같은 1라운드 안의 재대결(`round` 증가)에서는 개인 승/무/패 누적을 유지한다.
- `다시한판`, 새 로비 시작, 새 `gameRound` 시작 시에는 참가자별 `wins/losses/draws/penalties`를 0으로 초기화한다.
- `result` 상태에서 최종 종료 조건이 만족되어 `game_over`로 전환될 때 결과 화면 렌더링 함수가 다시 호출될 수 있다.
- 이 재호출 시 DB 통계를 다시 더하면 한 번의 대결이 2승/2패/2무로 중복 집계되므로, 온라인 통계 저장은 호스트 판정 저장 함수에서만 1회 수행한다.
- 결과 화면 렌더링 함수는 저장된 통계를 읽어 표시만 하고, 온라인 DB의 `wins/losses/draws/penalties`를 다시 업데이트하면 안 된다.

## 상단 인디케이터 Fade Out

- 모든 iPhone/스마트폰 화면에서 게임 UI가 다이내믹 아일랜드, 스피커, 상태 인디케이터와 겹쳐 보이지 않도록 앱 전체 상단 fade out 마스크를 공통 적용한다.
- fade out 범위는 특정 기기(iPhone 17e)에만 의존하지 않고 `safe-area-inset-top`과 공통 최소 높이를 함께 사용한다.
- iPhone Pro, iPhone Air, iPhone 17e처럼 화면 폭과 노치 형태가 달라도 같은 상단 fade 규칙이 적용되어야 한다.
- 모바일 media query나 기기별 레이아웃이 앱 전체 마스크를 덮어쓰면 안 된다.
- 하단 브라우저/홈 인디케이터 영역도 기존처럼 하단 fade out을 유지한다.

## 벌칙 박스 색상

- 호스트 방 화면의 `이번 게임 벌칙` 박스는 참가자 화면과 같은 연한 주황 톤으로 맞춘다.
- 벌칙 라벨과 벌칙 텍스트는 왼쪽 정렬로 표시한다.
- 호스트 방 화면의 벌칙 박스는 `이번 게임 벌칙: 벌칙명`을 한 줄로 표시한다.
- 준비 화면의 한 줄 벌칙 안내도 라벨과 벌칙 값을 분리해서 표시한다.
- 실제 벌칙명은 라벨보다 더 진한 색상과 굵은 글씨로 표시해 명시도를 높인다.
- 긴 벌칙명은 한 줄 안에서 말줄임 처리한다.

## 다국어 표시 및 사용자 입력 벌칙

- 앱이 생성하는 제목, 상태, 버튼, 안내, 술래 수, 벌칙 미설정 문구는 각 참가자가 선택한 언어(한국어/영어/일본어)로 표시한다.
- 호스트가 직접 입력한 벌칙은 번역하지 않는 사용자 작성 콘텐츠로 취급한다.
- 입력된 벌칙은 호스트가 작성한 언어와 문구 그대로 모든 참가자 화면에 동일하게 표시한다.
- 벌칙이 비어 있을 때만 각 참가자의 선택 언어에 맞는 `벌칙 미설정` 안내를 표시한다.

## 카운트다운 및 결과 참가자 카드

- 영어와 일본어의 긴 카운트다운 문구는 확대 애니메이션 중과 원래 크기로 돌아온 뒤 모두 화면 폭 안에서 줄바꿈/축소되어 잘리지 않아야 한다.
- 대결 결과 참가자 카드에는 선택한 손 아이콘과 승/패/무 결과 배지만 표시한다.
- 결과 배지를 가리는 가위/바위/보 선택 텍스트는 결과 참가자 카드에서 제거한다.

## 앱 아이콘

- 한국어/영어/일본어 앱 아이콘은 제공된 각 언어별 최종 이미지로 교체한다.
- App Store 제출용 아이콘은 투명 영역을 제거한 불투명 PNG로 생성해 투명 부분이 검은색으로 보이지 않게 한다.
