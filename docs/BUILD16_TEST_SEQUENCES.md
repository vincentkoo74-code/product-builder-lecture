## 🎯 손 내는 규칙 (라운드 결과를 결정론적으로 만들기)
가위바위보 소거 규칙상 **딱 2종류만** 내면 진 쪽이 술래 후보가 된다. 테스트용으로 미리 약속:
- **이기는 쪽 = ✊바위 / 지는 쪽(술래 후보) = ✌️가위** (바위가 가위를 이김)
- **활성 M명 중 술래 N명 만들기**: N명 ✌️가위, (M−N)명 ✊바위 (딴 종류 금지)
- **전원 무승부**: ✊바위 + ✌️가위 + ✋보 세 종류 다 등장
- 손을 안 내면 5초 후 자동선택되니, 시점 테스트가 아니면 **일부러 늦게/동시에** 내서 상황 유도

## GROUP 2 — 다중술래 Defect 재현 (062, 핵심 Evidence) — 술래 **2명**, A·B·C·D 4인
> 목표: Fable5가 코드로 특정한 Defect A/B/C를 현장에서 재현·캡처. **각 게임 후 4기기 JSON 전부 수집.**

### SEQ-2.1 — Defect A 재현 (round-1 tooFew → 확정 술래가 재대결로 복귀?)
1. A가 **술래 2명**으로 게임 시작.
2. **라운드 1**: 활성 4명 중 **1명만 가위**(=술래 후보 1), 나머지 3명 바위. → 결과: "1명 술래 확정, 3명 재대결"(tooFew) 이 떠야 정상.
3. 🔴 **여기서 아무도 3~5초간 화면을 건드리지 말 것**(auto-advance 2.6초 창에 5초 폴링이 겹치는 걸 노림).
4. **관찰**: 재대결이 **3명(승자)끼리만** 이어지는가(정상)? 아니면 **방금 술래 확정된 사람이 다시 끌려 들어오거나 전원이 처음부터 재시작**되는가(= Defect A 재현)?
5. **1~5회 반복**(약 50% 확률). 재현되면 그 게임 라운드/상황 메모 + 4기기 JSON.

### SEQ-2.2 — 술래 2명 정상 진행 4갈래 (tooMany/tooFew/exact/draw)
같은 방에서 라운드를 이어가며 4가지를 각각 1회씩 유도, 매 라운드 화면 전이가 **다중술래 정상 진행**인지 확인:
- **tooMany**: 활성 4명 중 **3명 가위**(술래후보 3 > 남은슬롯 2) → 진 3명끼리 재대결로 이어져야.
- **tooFew**: 활성 3명 중 **1명 가위** → 1명 확정, 승자 재대결.
- **exact**: 활성에서 **정확히 남은슬롯 수만큼 가위** → game_over(최종 결과).
- **draw**: 활성 전원이 **바위/가위/보 섞어** → 무승부 재대결.
- **관찰**: 어느 하나라도 "**게임 전체가 처음부터 재시작**"으로 튀면 → 라운드/상황 메모(062).

### SEQ-2.3 — Defect C 재현 (game_over 도달 시 비호스트 고착?)
1. 라운드를 진행해 **술래가 목표 2명에 도달**(예: tooMany로 2명 이상 확정되는 흐름).
2. **관찰**: **비호스트(B·C·D)** 기기가 최종 결과/통계로 넘어가는가? 아니면 **결과 화면에 멈춰**(고착) 있는가?(= Defect C)
3. 고착 시 어느 기기·몇 초 후에도 안 풀리는지 메모.

### SEQ-2.4 — Defect B 관찰형 (멤버 그대로 호스트만 바뀜)
- 다중술래 진행 중 **아무도 안 나갔는데 HOST 배지가 갑자기 다른 기기로 옮겨가는** 순간이 보이면 → 그 직후 **게임이 전체 재시작되는지** 관찰. (수동 유도 어려움 — 보이면 캡처)

## GROUP 3 — 동기화 편차 & 지연 (058/059/060) — 3~4기기, 나란히 놓고
> 가능하면 **기기들을 나란히 두고 한 번에 영상 촬영**(시점 차이는 눈보다 영상이 정확). 한 기기만 LTE로 편차 유도.

- **SEQ-3.1 (058 카운트다운)** 매 라운드 **"가위바위보" 5초 카운트다운의 시작/끝 시점**이 기기 간 눈에 띄게 어긋나는가?
- **SEQ-3.2 (059 결과 전환)** 라운드 종료 후 **결과 화면으로 넘어가는 시점**이 기기 간 다른가?
- **SEQ-3.3 (060 지연 급증)** **한 게임을 10라운드 이상** 연속(무승부 유도로 라운드 늘리기) → **6라운드 이후** 화면 전환/결과 노출이 **느려지는지** 라운드 번호와 함께 메모.
- 계측이 drift/latency를 자동 기록 → **전 기기 JSON이 핵심 Evidence**.

## GROUP 4 — 방 생명주기 & 복구 (056/054/061)
- **SEQ-4.1 (056-A 통계 누적, 회귀 핵심)** A·B·C **멤버 그대로 3판 연속** → 각자 내기록(통계)이 **3판 누적**인가? (매판 리셋되면 회귀!)
- **SEQ-4.2 (056-B 세션 분리)** 위 상태에서 **C 나가고 D 입장**(또는 C 재입장) → 새 게임 → 전적이 **이전 멤버 기록과 안 섞임** 확인.
- **SEQ-4.3 (056 1인 방 폭파)** B·C 모두 나가 **A만 남김** → A에 "혼자 남아 방 종료" 토스트 + 홈 이동. (방 생성 직후 혼자 대기는 폭파 안 됨 — 별도 확인)
- **SEQ-4.4 (061 결과화면 고착 복구)** 결과 화면 표시 중 **한 명이 나감** → 남은 기기가 **최대 ~3초 내 자동 재동기화**(고착 안 됨).
- **SEQ-4.5 (054 재초대 반복)** 게임 종료 후 A가 **재초대 → 취소 → 재초대**를 3~4회 → 매번 **B·C 전원**에게 초대 뜨는가?
