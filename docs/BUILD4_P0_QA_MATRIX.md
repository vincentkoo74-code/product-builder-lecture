> 작성: Claude (Opus 4.8). 단위 테스트(`npm test`, 39 케이스)는 통과했으나,
> **완료 처리는 아래 실기기 멀티디바이스 결과를 모두 채운 뒤에만** 한다.
> "참가자 N명" = **비호스트 플레이어 수**(호스트는 심판, 가위바위보를 내지 않음).

## 0. 자동 검증으로 이미 보장된 것 (코드/로직)
- 술래 소거 루프가 모든 (3/4/5명 × 술래 1..N-1) 조합에서 **정확한 술래 수로 수렴**하고 멈추지 않음 — `tests/elimination.test.mjs`.
- 확정 술래는 재게임 활성 집합에서 **항상 제외**, 호스트는 어떤 조합에서도 술래/활성에 포함되지 않음.
- 중도 퇴장으로 활성자가 남은 슬롯 이하가 되면 **전원 술래 확정·종료**(1명 무한 무승부 deadlock 방지).
- **술래 수 상한 = 비호스트 수 − 1** (호스트 포함 계산 시 발생하던 deadlock 수정).
- 전적 집계는 게임 종료 시 **권위 DB 행** 스냅샷으로 통일(전원 동일).

> 위는 "로직"이 맞다는 것이지 "기기 간 실시간 동기화"가 맞다는 보장이 아니다 → 아래 실기기 QA 필수.

## 1. 환경
- 기기: 최소 2대(호스트 1 + 참가자 N). 5명 시나리오는 호스트 포함 6대 권장(또는 브라우저 탭 혼용).
- 빌드: `npm run build:web && npx cap sync` 후 각 기기에 설치/접속.
- 네트워크: 동일 Wi-Fi 권장. Realtime + 5초 폴링 백업 동작 확인.

## 3. 시나리오별 절차 / 기대 결과
1. **참가자 수 변경(1→5→1)**: 입·퇴장마다 모든 기기 목록이 실시간 갱신, 서버 상태 일치, 게임 진행 가능.
2. **술래 수 설정**: 플레이어 수에 따라 드롭다운이 **1..(플레이어−1)**만 노출(3명→1,2 / 4명→1,2,3 / 5명→1,2,3,4). 변경이 전 기기/서버 반영.
3. **게임 시작**: 호스트 시작 가능 + 활성 전원 Ready 시 **자동 시작** + 마지막 Ready가 트리거.
4. **다중 술래 재게임**: 패자 확정 후 **남은 활성자만** 재대결, 목표 술래 수 도달 시 종료.
5. **확정 술래 제외**: 확정자는 재게임에서 Ready/선택 불가, 대기 화면 유지.
6. **호스트 패배**: (심판 모델) 호스트는 술래가 되지 않음 → 호스트가 술래로 표시되거나 진행이 막히면 **버그**.
7. **중도 퇴장**: 라운드 중/사이 퇴장 시 세션 유지·재계산·게임 지속, 멈춤 없음.
8. **QR 재입장(강제종료 후)**: 이전 게임 화면 복원 안 됨, 새 방 정상 입장, UI 정상.
9. **전적 집계**: 종료 후 홈→이전 게임 전적이 **모든 기기에서 동일**하고 실제 승/패/무/승률과 일치.
10. **상태 전이**: LOBBY→READY→PLAYING→RESULT→NEXT_ROUND→FINISHED 정상, Deadlock/Freeze/Infinite Waiting 없음.
