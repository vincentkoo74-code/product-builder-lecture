# BUILD16 실기기 QA 점검 시나리오

> 대상: TestFlight **build 16** (자동 QA 계측 ON, `__QA_BUILD__=true`). 생성 2026-07-02.
> 목적: (A) 이번에 반영한 신뢰성 Fix 5건 검증, (B) Evidence-gated 이슈(062/058/059/060) 실기기 Evidence 수집.
> 원장: `docs/BUILD16_QA_PLAN.md`. 결과는 이 문서 하단 템플릿에 기록 → `node scripts/qa-report.mjs` 분석.

## 0. 준비 (Setup)

- **기기**: 최소 **3대**(가위바위보는 3인+ 다중술래 검증 필요). 가능하면 iPhone×2 + iPad×1로 화면 크기 교차 확인. 기기 라벨 = **A(호스트)·B·C** (필요 시 D).
- **빌드**: 세 기기 모두 TestFlight에서 build 16 설치. 설정에서 build 번호 **16** 확인.
- **QA 계측 확인**: 앱 우하단에 **`QA📋`** 버튼이 보이면 계측 ON 정상. (안 보이면 build 16이 아님 — 재설치)
- **네트워크**: 실제 사용 환경(LTE/5G 혼합 권장 — drift 재현). 필요 시 한 기기만 Wi-Fi로 두어 지연 편차 유도.
- **로그 캡처 방법**(둘 중 하나):
  - 간편: 각 기기에서 `QA📋` 탭 → 클립보드 복사(요약+최근50) → 메모/메신저로 전달.
  - 전체: Mac Safari 웹인스펙터 콘솔에서 `copy(JSON.stringify(__qaMetrics.export()))` → 전체 metrics+manifest+snapshots.
- **원칙**: **사용자는 플레이만** 한다. 앱이 QA Record를 자동으로 남긴다. 이상 현상은 "어느 기기에서/몇 라운드에" 발생했는지만 메모.

## B. Evidence 수집 시나리오 (Evidence-gated — 판정 없이 데이터만)

> 이 항목들은 **수정 대상이 아니라 재현·측정** 목적. 이상 발생 시 **어느 기기/몇 라운드/무슨 화면**인지 메모 + 각 기기 `QA📋` 또는 `__qaMetrics.export()` JSON을 **전원 수집**해 전달.

### E1 — WRPS-062 다중 술래 흐름 (전체 재게임 오전환)
- **전제**: **4인**(A·B·C·D), **술래 2명** 설정.
- **단계**: 여러 라운드 진행하며 다음을 의도적으로 유도:
  - (a) 한 라운드에 **술래 후보가 2명 초과**(tooMany) 나오게 → 패자끼리 재대결로 이어지는지.
  - (b) **술래가 목표보다 적게**(tooFew) 나오게 → 승자끼리 재대결로 이어지는지.
  - (c) 라운드 **전원 무승부** 발생 → 재대결로 이어지는지.
  - (d) 다중술래 진행 중 **한 명 이탈**.
- **관찰(Expected 후보)**: 위 각 경우가 **다중술래 정상 진행**으로 이어져야 함. **"게임 전체가 처음부터 재시작"으로 잘못 전환되면 그 시점 기록**(라운드 번호·직전 액션·기기).
- Evidence: 전 기기 JSON + 오전환 재현 메모.

### E2 — WRPS-058/059/060 동기화 편차 & 지연
- **전제**: 3인+, 기기별 네트워크 편차(한 대 LTE).
- **단계**: ① **10라운드 이상** 연속 플레이. ② 각 라운드에서 **선택 5초 카운트다운의 시작/종료 시점**이 기기 간 눈에 띄게 다른지. ③ **결과 화면 전환 시점**이 기기 간 다른지. ④ 특히 **6라운드 이후** 화면 전환/결과 노출이 **느려지는지**(지연 급증).
- **관찰**: 이상 시 라운드 번호 메모. 계측이 자동으로 drift/latency를 기록하므로 **전 기기 JSON 수집이 핵심**.
- Evidence: 전 기기 `__qaMetrics.export()` JSON(10R+).
